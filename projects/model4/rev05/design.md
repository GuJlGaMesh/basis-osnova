# Исправление нативного импорта r05

В r04 выделение мышью воспроизводило Access violation 0078DAE4, чтение 00000258. Очищенный от персональных данных стек: `TObject3D.GetIsList` → `THoleDrilling.AddBodies` → `THoleDrilling.FindConnectedFasteners` → `TDefaultAction.HighlightFasteners` → `TDefaultAction.MessageHandler`. Ошибка возникает при обходе связанных объектов для подсветки; конкретная повреждённая ссылка не установлена.

Полный узел сохранён штатной командой БАЗИС в `src/lib/native-module.fr3d`. Импорт выполняется через `OpenFurniture(...).MountBox(...)`, затем `Owner=Model` и `Build()` до растяжения. После растяжения измеряются панели и вычисляется перенос по боковине и лицу. Эластичный узел переносится в корень с сохранением мировой позы; удаляется только пустой монтажный контейнер. Рабочая реализация: [model4.js](src/model4.js).

| Операция | Основание и результат в API 2341 |
|---|---|
| OpenFurniture / MountBox | Локальная справка API и выполнение в целевой среде; создан полный нативный узел |
| Owner / Build | Проверены на 27 размерах; Build до ElasticResize обязателен для корректного положения стекла и фурнитуры |
| ElasticResize / IsElastic | Принятые размеры сопоставлены с запросом, все выгруженные объекты сравнены с нативным эталоном |
| ToGlobal / NToGlobal / OrientGCS | Мировая поза сохранена при переносе узла к Model |
| DeleteObject | Удаление оболочки MountBox выполнено в том же запуске без сбоя; старые объекты сохранены |
| SaveModel / LoadModel | Только диагностический сценарий: сохранение отдельной копии и равенство выгрузки после открытия |

Неудачные опыты: оболочка `AddBlock().Load` воспроизводила ошибку выделения как для B3D, так и для FR3D; поздние Build и Action.Commit не исправляли её. Удаление этой оболочки в том же запуске давало 00B8C179 / чтение 00000020; Undo.RecursiveChanging и повторное назначение владельца не помогли. Отдельное удаление в следующем скрипте не является самостоятельным решением генератора. MountBox без предварительного Build давал 27 расхождений геометрии на крайнем размере; добавление Build до растяжения устранило их.

Рамка сохранённого фрагмента может зависеть от точки привязки. Поэтому вставка опирается на измеренные панели после растяжения, а не на предполагаемый ноль FR3D. Для новых размеров каждый экземпляр создаётся из неизменного шаблона. Обратимость произвольного многократного растяжения уже существующего экземпляра не заявляется: ограничения вложенных рамок исходника требуют отдельной проверки.
