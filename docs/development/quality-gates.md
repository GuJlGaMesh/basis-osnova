# Quality gates модели

Gate — обязательная точка проверки с критерием и доказательством. Таблица задаёт процесс проекта, а не готовый автоматический проверяющий модуль БАЗИС.

## Статусы и принятие решения

Для каждой проверки использовать `PASS`, `FAIL`, `NOT_RUN` или `N/A`. `PASS` требует доказательства; `FAIL` означает обнаруженное несоответствие; `NOT_RUN` — нет доступа, данных или проверка не выполнена; `N/A` требует обоснования неприменимости. Отсутствие фасадов может делать проверку их движения неприменимой; отсутствие нужного инструмента — только `NOT_RUN`.

Обязательный gate с `FAIL` или `NOT_RUN` блокирует соответствующий следующий этап. Нельзя усреднять результаты или перекрывать провал количеством успешных пунктов. Частично пройденный gate остаётся `FAIL` при дефекте либо `NOT_RUN` при недостатке доказательств. `N/A` не допускается для G0, G1, G2, G3, G7; G8 обязателен для изготовления.

| Gate | Когда | Критерий PASS | Минимальное доказательство |
|---|---|---|---|
| G0. Исходные данные | До построения | Критические размеры и решения подтверждены; размерные определения, единицы и противоречия разрешены; производственные неизвестные перечислены | Паспорт с источниками и подтверждением конкретной ревизии |
| G1. Расчёт | До построения | Все детали имеют конечные положительные размеры; цепи замыкаются по Ш/В/Г; толщина, зазоры и врезки учтены; согласованы критерии измерения | Таблица ожидаемых деталей, формулы, ручной контроль хотя бы одного узла каждого типа |
| G2. Построение и целостность | После построения | Нет ошибок выполнения, пропусков, непреднамеренных дублей и лишних объектов; панели распознаются как нужные типы; чужие объекты сохранены | Лог или запись действий, дерево модели, сопоставление ID и количества с расчётом |
| G3. Геометрия | После построения и повторного открытия | Фактические габариты и проёмы соответствуют паспорту; позиции и ориентации корректны; нет вырожденных контуров и непредусмотренных коллизий | Измерения из модели с ожидаемым/фактическим значением, обзорные виды и сечения спорных узлов |
| G4. Материалы и кромки | До деталировки | Материал, толщина, текстура, кромки каждой детали соответствуют паспорту; размеры заготовок учитывают согласованную технологию | Ведомость деталей из модели, свойства и карта кромок; контроль готового размера против размера заготовки |
| G5. Фурнитура и присадка | До выпуска | Все артикулы и установки подтверждены; отверстия и пазы согласованы с ответными деталями; нет непредусмотренных выходов и конфликтов | Спецификация фурнитуры, монтажные схемы, размеры/сечения присадки по каждому типу соединения |
| G6. Работа и сборка | До выпуска | Проверены траектории подвижных частей, инструментальный доступ, порядок сборки, установка, нагрузки и устойчивость | Положения/траектории, схема сборки и монтажа, расчёт или документация по нагрузке и креплению |
| G7. Сохранение и выдача | Перед передачей модели | Нативный файл сохранён и повторно открыт; свойства и объекты сохранились; деталировка и чертежи согласованы с этой ревизией; все необходимые файлы доступны | Путь и SHA-256 файла, версия приложения, результат повторного открытия, перечень экспортов и сверка позиций |
| G8. Производственный допуск | Перед изготовлением | G0–G7 закрыты в применимой части; технолог подтвердил материалы, операции, допуски, сборку и монтаж; при ЧПУ отдельно проверен производственный маршрут | Имя/роль проверяющего, дата, ревизия, решение и подтверждённый состав производственного пакета |

G0/G1 блокируют построение проверяемой модели; черновик с явными допущениями регулируется [правилами](rules.md). G2–G7 блокируют статус проверенной модели. G8 блокирует изготовление. Для чисто декоративного эскиза применимость производственных проверок указывают явно; статус остаётся «ЭСКИЗ».

## Методика измерений

Габариты вычислять или измерять по фактической геометрии, включая элементы, включённые в определение габарита паспорта. В протоколе указывать состав измеряемых объектов. Проверять все уникальные детали и узлы; одинаковые экземпляры можно группировать только при подтверждённой идентичности геометрии, ориентации и технологии. Зеркальные детали проверять отдельно.

Для скалярного размера критерий: `abs(actual − expected) ≤ epsilon`. Значение `epsilon`, единица и метод измерения должны быть согласованы в паспорте. Не использовать округление изображения как допуск. Численная погрешность CAD, производственный допуск, монтажный и функциональный зазоры — разные величины.

Скриншот общего вида не доказывает глубину отверстия, материал или отсутствие скрытых пересечений. Если нет программного доступа к геометрии, нужны ручные измерения и сечения в БАЗИС с записью проверяющего. Проверка движения только в крайних положениях не доказывает отсутствие столкновений между ними: проверить весь путь доступным средством либо геометрическим анализом с явным описанием метода.

## Шаблон qa.md

```markdown
# Протокол проверки
Изделие и ревизия: [ID/rev]
Паспорт / исходники: [пути и ревизии]
Модель: [путь, SHA-256]
Среда: [версия/сборка БАЗИС, API, библиотеки]
Проверяющий и дата: [значение]
Режим: [эскиз / модель / к изготовлению]

| Gate | Статус | Метод и ожидаемый результат | Фактический результат | Доказательство | Дефект/причина N/A |
|---|---|---|---|---|---|
| G0 | NOT_RUN | | | | |
| G1 | NOT_RUN | | | | |
| G2 | NOT_RUN | | | | |
| G3 | NOT_RUN | | | | |
| G4 | NOT_RUN | | | | |
| G5 | NOT_RUN | | | | |
| G6 | NOT_RUN | | | | |
| G7 | NOT_RUN | | | | |
| G8 | NOT_RUN | | | | |

## Измерения
| ID детали/узла | Параметр | Ожидается, мм | Факт, мм | Допуск, мм | Результат | Доказательство |
|---|---|---|---|---|---|---|

## Дефекты
[ID, затронутые детали, серьёзность, исправление, повторная проверка]
## Решение
[ЭСКИЗ / НЕ ПРОВЕРЕНО / ТРЕБУЕТ ИСПРАВЛЕНИЯ / МОДЕЛЬ ПРОВЕРЕНА / ДОПУЩЕНО ТЕХНОЛОГОМ]
[оставшиеся ограничения и основание решения]
```

Любой `FAIL` → «ТРЕБУЕТ ИСПРАВЛЕНИЯ». Без дефектов, но с обязательными `NOT_RUN` в G0–G7 → «НЕ ПРОВЕРЕНО». Все применимые G0–G7 закрыты → «МОДЕЛЬ ПРОВЕРЕНА». Для «ДОПУЩЕНО ТЕХНОЛОГОМ» дополнительно необходим `PASS` G8. Эскиз никогда не получает производственный статус.

После изменения модели аннулировать прежний общий вердикт, обновить ревизию и доказательства. Повторить затронутые gates и G2/G3/G7 на итоговом файле; производственный допуск пересогласовать. Предыдущие результаты можно использовать только при обоснованной неизменности соответствующей части.
