# Обязательные правила

1. Перед построением заполнить [паспорт](intake.md). Для каждого параметра различать подтверждённое значение, вычисленное значение, предложение и неизвестное.
2. Критические неизвестные блокируют зависимые действия. Можно продолжать независимые расчёты и документацию. Черновая геометрия с допущениями допустима только по явному запросу пользователя и с маркировкой «ЭСКИЗ».
3. Все линейные размеры хранить в миллиметрах, углы — в градусах в паспорте; преобразования в API проверять отдельно. Различать размер ниши, наружный габарит, размер корпуса, чистый проём, размер готовой детали и заготовки.
4. Конструировать по [правилам моделирования](modeling.md); изменения габаритов и материалов должны пересчитывать все зависимые элементы.
5. Использовать только подтверждённые операции среды по [процессу БАЗИС](bazis.md). Не выдумывать API, файловые форматы, пункты меню и встроенные проверки.
6. Проверять результат по [quality gates](quality-gates.md); отсутствие доказательства не подменять уверенностью или успешным запуском скрипта.
7. Сохранять пользовательские модели и библиотеки. Эксперименты выполнять на копии; генератор должен явно определять, какими объектами он владеет.
8. Документировать источник конструктивных решений. Примеры размеров и учебные формулы не становятся стандартами производства.
9. Общие документы писать официально и точно, без разговорных выражений. Не сохранять в репозитории ключи лицензий, пароли и лишние персональные данные заказчика.
10. Перед выдачей выполнить [ревью](review.md) и [процедуру выпуска](releases.md). Коммит и публикация выполняются по запросу пользователя.
