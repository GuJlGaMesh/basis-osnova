# Проверки и регрессия

Основные критерии и шаблон протокола — в [quality gates](quality-gates.md). В проекте не установлен автоматический CAD-валидатор: каждый результат помечают фактическим способом получения — расчёт, API, измерение в интерфейсе или проверка специалистом.

Сначала агент закрывает S0–S3 для выдачи скрипта. Проверки в БАЗИС выполняет человек или агент при доступном управлении и разрешении пользователя; они отражаются в G0–G8. Отсутствие локального приложения не считается провалом подготовки скрипта и не превращает проверки модели в PASS.

## Уровни проверки

1. Независимый расчёт проверяет размерные цепи и невозможные параметры до запуска.
2. Проверка в целевой версии БАЗИС подтверждает создание объектов, операции, измерения, повторный запуск и отмену.
3. Сохранение и повторное открытие проверяют итоговый артефакт, а сверка ведомостей — его связь с выдачей.
4. Технологический контроль проверяет производственную пригодность и сборку.

Unit-тесты независимого расчёта полезны при появлении генератора. Они не заменяют уровни 2–4. Тестовый инструмент выбирают вместе с реализацией, а не объявляют несуществующие команды запуска.

## Минимальные сценарии для генератора

| Случай | Ожидание |
|---|---|
| Учебный корпус из [правил моделирования](modeling.md) | 4 панели, размеры 720×400 (2 шт.) и 564×400 (2 шт.), габарит 600×720×400; сверить фактический результат |
| Ноль, отрицательное число, пустота, текст, бесконечность | Отказ до изменения модели; сообщение называет параметр |
| W≤2t или H≤2t в учебной схеме | Отказ: нет положительного внутреннего проёма |
| Изменение t с 18 до 16 при прежних W/H/D | Дно и крышка 568×400, внутренний проём 568×688; наружный габарит прежний |
| Разные Ш/В/Г, несимметричное изделие | Оси не переставлены, левая и правая стороны не перепутаны |
| Поворот и вложение в блок | Мировые размеры и сопряжения сохраняются, кромки и присадка на нужных сторонах |
| Уже пустая модель, в том числе со служебной рамкой | Новая сборка добавляется; рамка не считается изделием |
| Модель содержит панели, сборки и скрытые/вложенные объекты | Все прежние объекты сохраняются без изменения; новая сборка добавляется отдельно |
| Повторный запуск, в том числе после ручных правок | Добавлен ещё один экземпляр, предыдущий и его правки неизменны |
| Отмена ввода или неверные параметры до вставки | Текущее содержимое не меняется |
| Ошибка загрузки новой сборки | Старая сцена сохранена, ошибка сообщена |
| Ошибка после начала вставки | Удаляется только собственный новый контейнер, прежние объекты сохраняются |
| Недоступен материал, артикул или метод API | Явная ошибка, без молчаливой замены |
| Загрузка настроек другой ревизии или отсутствующей библиотеки | Несовместимые параметры отклонены до изменения сцены |
| Предварительный просмотр, подтверждение и отмена | Изменяются только объекты текущего действия; отмена восстанавливает предыдущее состояние |
| Явное редактирование параметрического экземпляра после открытия файла | Зависимые детали пересчитаны; другой экземпляр и его параметры не изменены |
| Все промежутки полок заданы, часть автоматическая, места недостаточно | Размерная цепь сверена; деления на ноль нет; недопустимый набор отклонён до построения |
| Скругление, вырез или зеркалирование сложного контура | Форма и площадь соответствуют расчёту; кромки и обработки остались на предусмотренных участках |
| Паз с разных пластей, в том числе на повёрнутой панели | Траектория, сечение, сторона и глубина соответствуют заданию |
| Сохранение и повторное открытие | ID, количество, геометрия, материалы и операции сопоставимы с результатом до сохранения |
| Доступ к связанным объектам | После построения и повторного открытия программно проверить панели и связанные крепежи; диагностику мышью и её фактическое покрытие фиксировать отдельно по правилам проверки редактирования |

Для фасадов, ящиков, пазов и конкретной фурнитуры добавляют собственные случаи по монтажным схемам. Граничные значения выбирают по реальным ограничениям, а не случайными «обычными» числами.

При вставке двух модулей разной глубины измерить лицевые плоскости: они совпадают, разница глубины находится сзади. Сравнить полные выгрузки старых объектов до/после; количество новых объектов проверять отдельно от служебных рамок.

## Диагностика деталей и связей

Каждое замечание связывать с конкретным экземпляром детали и кодом проверки, указывать фактическое значение, ожидаемое ограничение, его источник и статус. Выгрузка обозначает единицы и систему координат; имена деталей не заменяют идентификаторы, поскольку могут повторяться. Сбор замечаний не должен менять материалы, кромки, владельцев или геометрию и вызывать перестроение деталей. Подсветка найденного и исправление — отдельные действия.

| Проверка | Критерий и ограничение |
|---|---|
| Заготовка помещается на листе | Проверять обе стороны листа, припуски, направление текстуры и разрешённый поворот. Ограничения задаются конкретным материалом, не подстрокой его названия; пригодность отдельной заготовки не подтверждает раскрой заказа |
| Открытый торец без кромки | Сопоставить элементы контура с кромками и проверить видимость средствами подтверждённого API. Порог расстояния и исключения определяются конструкцией; видимый торец не всегда требует облицовки |
| Кромка на дуге или вогнутом участке | Радиус, материал и способ обработки соответствуют ограничениям технологии; универсального минимального радиуса нет |
| Связи крепежа | Выгрузить отношения «панель → крепёж → связанные детали», проверить ожидаемые соединения и отсутствие ссылок на удалённые объекты. Не требовать ровно двух панелей для любого типа крепежа |
| Объём и масса | Не подменять объём фигурной детали произведением габаритов. Учитывать контур, толщину и обработки в пределах возможностей измерения; плотность брать для конкретного материала, приближения обозначать явно |

Для графа соединений методы наподобие `FindConnectedFasteners` и `FindFastenedObjects` сначала проверять на отдельной рабочей копии. Сопоставлять отношения до сохранения и после повторного открытия; успешная выгрузка не заменяет проверку редактирования и выделения. Ошибка или отсутствие доступного API не превращается в пустой отчёт без замечаний.

Для пакетной диагностики проверять независимость выходов, отсутствие перезаписи входных файлов и восстановление состояния после ошибки отдельного документа. Журнал содержит не только успешные файлы, но и ошибки и пропуски с причиной. Порядок пакетного запуска описан в [работе со скриптами](bazis.md#пакетная-обработка).

## Регрессия компоновки модулей

Для возможностей из [правил компоновки](modular-layouts.md) выбирать случаи по поддерживаемым вариантам. Неподдерживаемая комбинация должна явно отклоняться; количество модулей ограничивается подтверждёнными возможностями генератора и среды, а не числом из демонстрационного примера.

| Случай | Ожидание |
|---|---|
| Один модуль и тот же модуль в составе ряда | Локальная конструкция одинакова при одинаковых входах; отличия на стыке заданы явно |
| Перестановка модулей, переход между страницами, смена типа | Настройки остаются у правильных ID; несовместимые параметры не применяются к новому типу |
| Смена общего параметра при локальном переопределении | Переопределение сохранено или сброшено явно; итоговое значение видно |
| Скрытие фасадов и последующее отображение | Количество деталей, геометрия и ведомость не меняются |
| Левый и правый поворот, угловой модуль в каждом из двух рядов | Положение, стороны открытия и размерные цепи соответствуют выбранному варианту |
| Планка включена/отключена, тип дна и фасадной системы изменён | Пересчитаны угловой модуль и зависимые детали соседей, нет дублирования общих деталей |
| Разное число секций в верхнем и нижнем рядах | Явно заданные оси техники и линии фасадов совмещены независимо от нумерации |
| Фрагмент с другой точкой привязки или ориентацией | Адаптер обеспечивает нужную установку либо отклоняет несовместимый фрагмент; ручная поправка не скрывает ошибку |
| Изменение навесов, задника или царг | Опорные участки, вырезы, связи и обработки соответствуют выбранной схеме |
| Техника, профиль захвата и задняя стенка конкурируют за место | Недопустимое пересечение и нарушение монтажных объёмов обнаружены до выпуска |
| Общий профиль на границе секций или двух запусков | Артикул, отделка, стыки, длины и окончания согласованы; нет пропуска или двойного учёта |

## Регрессия мебельных конструкций

Сценарии выбирают по типам узлов и требованиям генератора, независимо от имени исходного файла. Если для сравнения нужна готовая модель, подготовить проверенный эталон по [правилам работы с примерами](reference-models.md). Учебный пример без подтверждённых параметров не задаёт численный результат PASS/FAIL.

| Случай | Ожидание после подготовки проверенного эталона |
|---|---|
| Воспроизведение исходной конструкции | Совпадают проверенные габариты, состав сборок, материалы, кромки и операции; сравнение по свойствам, не по байтам CAD-файла |
| Несколько ящиков за разным числом фасадов | Внутренние ящики не пропущены; доступ и порядок открывания сохранены |
| Смена исполнения или длины направляющей | Размеры деталей и присадка пересчитаны по применимой схеме; неподдерживаемая комбинация отклонена |
| Смена профиля GOLA | Перепроверены обработка корпуса, крепления, фасады, захват и траектории |
| Смена толщины панели или кромки | Свойства и ведомость согласованы; пересчитаны проёмы, заготовки и соединения |
| Смена техники или верхних связей | Повторно проверены монтажный объём, вырез, вентиляция и доступ к подключению |
| Смена установочной высоты опор | Пересчитан общий габарит; проверены регулировка, нагрузка и цоколь |
| Смена модели встроенного холодильника | Заново проверены ниша, вентиляция, масса/размеры фасадов и система их крепления |
| Решётка или полка уменьшает проход воздуха | Расчёт выявляет нарушение свободного сечения или непрерывности канала до принятия конструкции |
| Смена door-on-door на sliding | Заново выбраны крепления, мебельные петли и присадка; старая схема не сохраняется автоматически |

Для изменённых параметров ожидаемый результат вычисляют независимо по утверждённой схеме, а не копируют из исходного файла. Доказательства всегда связывают с хешем конкретной модели и профилем среды.

## Регрессия эластичности

Проверять исходный размер, минимум и максимум каждой оси, совместные крайние сочетания, повторный запуск и изменение размера после сохранения и повторного открытия. Отдельно выполнить увеличение → уменьшение → возврат к исходному размеру: это выявляет накопление смещений.

Независимо измерять толщины плит, фасадные зазоры, сечения профилей, длину направляющих, положение опор, положительность контуров и согласованность присадки. Сопоставлять запрошенный и принятый API размеры. Параметры вне поддержанного диапазона и отмена ввода должны оставлять модель неизменной. Проверка свойств по API не заменяет проверку движения, коллизий и технологической присадки.

## Проверка пакета для ручного запуска

Проверить файл `.js`, все обязательные функции, список зависимостей и соответствие инструкции исходнику. Проверку синтаксиса совместимым инструментом и независимые расчёты выполнить до выдачи, указав инструмент и его границы; не запускать CAD-код через Node.js вместо БАЗИС. Для обязательного ввода проверить пустые/нечисловые/недопустимые значения и отмену. Не считать наличие описанной проверки доказательством её выполнения.

В инструкции оператору задать ожидаемую структуру результата и контрольные размеры, путь сохранения модели и набор доказательств для возврата. Для ошибки нужны текст ошибки, строка скрипта, фактические входные данные и сборка БАЗИС. Исправленный скрипт получает новую ревизию и повторную подготовительную проверку; модель затем проверяется после нового запуска.

## Проверка документации

Проверять существование относительных ссылок, наличие входа из `AGENTS.md`, согласованность статусов, определений размеров и шаблонов. Учебные расчёты перепроверять независимо. Новая версия API требует перепроверки примеров, а не только замены года в тексте.

## Регрессия нативного импорта

Для связанной сборки сравнивать дерево, материалы, контуры, кромки и мировые преобразования всех доступных объектов при исходном, минимальном и максимальном размерах. Проверять порядок инициализации по [model-to-script.md](model-to-script.md#импорт-связанной-нативной-сборки), неизменность существующих объектов, нулевой боковой зазор, общую лицевую плоскость и равенство выгрузки после повторного открытия. Допуск измерений задавать явно.

Проверка выделения через API и диагностика мышью имеют разные области покрытия; правила и ограничения описаны в [проверке редактирования](model-to-script.md#проверка-возможности-редактирования). Не требовать участия агента для обычного запуска уже проверенного генератора. При новом сбое аннулировать затронутый PASS прежней ревизии, сохранив достоверные результаты геометрических проверок.
