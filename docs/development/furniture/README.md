# Выбор карточки мебели

Выбрать базовую карточку по изделию; дополнительные открывать только для реально присутствующих узлов. В карточке находятся специальные входы, конструктивные ограничения и проверки. Общий паспорт заполняется по [intake.md](../intake.md); общая геометрия — по [modeling.md](../modeling.md). Обязательные гейты определяются [этапом работы](../quality-gates.md), а не типом мебели.

| Изделие или узел | Карточка | Когда добавить другую |
|---|---|---|
| Шкаф, тумба, стеллаж, отдельный корпус и полки | [Корпусная мебель](cabinet.md) | Ящики → drawers; кухня/техника → kitchen; встроенный холодильник → refrigerator |
| Наружные и внутренние ящики, системы выдвижения | [Ящики](drawers.md) | Кухонный профиль захвата и опоры → kitchen |
| Кухонный ряд, угол, верхние модули, мойка, варочная, духовка, вытяжка, GOLA, цоколь | [Кухонные модули](kitchen.md) | Для ящиков и холодильника открыть соответствующую карточку |
| Корпус под встроенный холодильник или морозильник | [Холодильный модуль](refrigerator.md) | Присоединение к кухонному ряду → kitchen |

Если тип конструкции не покрыт, сначала определить входы и критерии в паспорте. Общую новую карточку создавать только для повторно применимых правил; название заказа или исходной модели не становится названием справочника. Для мягкой мебели, металлокаркаса и иных конструкций за пределами плитной корпусной мебели не подменять отсутствующие правила учебными формулами.

## Как поддерживать справочник

Каждый факт имеет одно место: общие правила → modeling, специальные входы/конструкция/проверки → карточка, границы API → bazis, критерии перехода → gates, результаты конкретного запуска → папка изделия. В карточке указывать применимость формул и нужные G-коды; не копировать определения PASS и комплект выдачи.
