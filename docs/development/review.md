# Ревью модели и изменений

При выдаче скрипта ревью начинается с паспорта, исходника и комплекта ручного запуска по S0–S3; после запуска человеком — с фактической модели по G0–G8. Критерии — [quality gates](quality-gates.md), ограничения — [правила](rules.md). Отсутствие локальной модели не является дефектом пакета скрипта, но не позволяет подтвердить результат построения.

При ревью скрипта проверяющий сопоставляет запрос, контракт входных параметров, формулы и реализованные операции. Проверяет, что предложения не стали исходными данными без ответа, обязательный ввод проверяется до построения, методы API имеют источник, повторный запуск и отмена определены, а учебный пример не выдан за производственный стандарт. При ревью модели после ручного запуска дополнительно сопоставляет реальные входные данные, детали, сохранённый файл и его экспорты.

При изменении размеров или толщины проверить расчёт зависимых проёмов, фасадов, полок, ящиков, кромок, присадки и монтажа; фактические свойства сверить после ручного запуска. При изменении только кода сначала проверить контракт и расчёты, затем оператор сравнивает геометрию и технологические свойства моделей, а не побайтовое равенство CAD-файлов.

Замечание должно содержать ID детали/параметра, ожидаемое и фактическое поведение, доказательство, последствия и требуемую повторную проверку. Дефект геометрии, монтажа, материала или производственных данных блокирует затронутый gate; косметическое замечание к описанию не должно скрывать этот блокер.

Не переносить в отчёт утверждения «прошло», если проверку не выполнили. Повторный просмотр собственного расчёта полезен, но не считается независимым измерением модели.
