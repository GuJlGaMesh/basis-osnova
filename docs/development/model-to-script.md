# Скрипт по существующей модели

Применять, когда `.b3d` или `.fr3d` служит исходником генератора. Сначала использовать уже полученные выгрузки и проверенные инструменты; повторять исследование только при изменении исходного файла, профиля API или недостаточном составе данных. Как отличать наблюдение от подтверждённого решения — в [reference-models.md](reference-models.md).

## Краткий маршрут

| Шаг | Действие и достаточный результат |
|---|---|
| 1. Найти готовую основу | Проверить материалы аналогичного изделия в `projects/`: инспектор, построение панелей, загрузку нативных узлов и сравнение результатов. Сопоставить хеш исходника, сборку БАЗИС и состав выгрузки. Не переносить размеры и артикулы другого изделия. |
| 2. Зафиксировать исходник | Сохранить неизменяемую копию и хеш; открыть отдельную рабочую копию. Заполнить [паспорт](intake.md), различая требуемую конструкцию и фактическое содержимое файла. |
| 3. Получить данные через API | За один рекурсивный обход выгрузить дерево, свойства панелей и преобразования по разделу ниже; записать ошибки чтения полей. Для папки примеров применять один инспектор и отдельные отчёты, а не читать каждую деталь через интерфейс. |
| 4. Выбрать способ переноса | Панели с реализованными операциями строить из описаний. Сложные библиотечные механизмы переносить нативно. Для неизвестной обработки реализовать и проверить её перенос либо сохранить соответствующий узел нативно; не исключать обработку молча. |
| 5. Собрать генератор | Проверить входы и зависимости → очистить текущую модель → загрузить шаблон → разрешить владельцев → построить панели → собрать зависимые узлы в эластичный блок → применить размеры → проверить результат. Контракт замены — в [bazis.md](bazis.md). |
| 6. Сверить и выпустить | Сравнить исходный размер, затем выполнить [регрессию эластичности](testing.md#регрессия-эластичности), повторный запуск, сохранение и повторное открытие. Выдать [комплект](releases.md) с отдельными статусами скрипта и модели. |

Готовая основа для адаптации: [инспектор модели](../../projects/model4/rev01/reference/inspect-model.js) и [эластичный генератор](../../projects/model4/rev02/src/model4.js). Это реализация конкретного изделия, не универсальный конвертер. Пути владельцев, допустимые обработки, размерные связи и зависимости проверять для нового исходника до запуска.

## Что выгружать и сохранять

Для каждого объекта записывать путь в дереве, имя, артикул, владельца, мировое начало координат и направления осей. Отдельно фиксировать служебную рамку документа, физические габариты изделия и рамку эластичного блока: общий `GabMin/GabMax` документа не является надёжной базой размеров изделия.

Для панелей сохранять толщину, материал, направление текстуры, исходный локальный контур с порядком и параметрами всех элементов, кромки с индексами привязки и фактическими свойствами. Записывать наличие обработок и облицовок; одного количества недостаточно для их воспроизведения. Неизвестное или недоступное поле отражать явно, а не считать отсутствующей операцией.

При создании шаблона без панелей заранее сохранить ссылки на удаляемые объекты: удаление меняет индексы соседей. Составить соответствие исходных путей владельцам в шаблоне и разрешить их до добавления новых панелей. Работать с копией, заранее сообщать о временно разобранной видимой сцене и восстанавливать полное изделие после извлечения. Нативный шаблон включать в зависимости выдачи.

## Ловушки реализации

Наблюдения относятся к профилю среды из [README](../../README.md#tech-stack). При его смене перепроверять затронутые вызовы короткой пробой в БАЗИС.

| Место | Рабочий приём |
|---|---|
| Вложенные объекты | Обходить `List`, `Count`, `Objects` рекурсивно. `AsList` в проверенной среде — метод; обращение как к свойству может пропустить вложенность. |
| Определение панели | Проверять подтверждённые панельные свойства `Contour` и `Butts`. Одно `Thickness` не отличает панель от профиля. |
| Координаты панели | Не переносить локальный контур в ноль без пересчёта преобразований. Назначить `Owner`, восстановить мировую ориентацию через `OrientGCS` и положение через `owner.ToObject(globalOrigin)`, затем выполнить `Build()`. |
| Контур и кромки | Сохранять порядок отрезков и дуг, направление дуг и `ElemIndex` кромок. Название материала не заменяет его фактическую толщину; компенсация определяется [правилами панелей](modeling.md#панели-и-материалы). |
| Смена владельца узла | До изменения `Owner` сохранить `ToGlobal` начала и `NToGlobal` направлений осей; после изменения восстановить мировую позу. Простое присваивание владельца может сместить или повернуть узел. |
| Эластичность | Проверять принятый размер, зависимости и неизменяемые размеры по [правилам эластичности](modeling.md#эластичное-изменение-размера). Наличие `IsElastic()` не доказывает правильность связей; ограничения вложенных блоков могут нарушать обратимость служебных рамок при уменьшении. |
| Подготовка JSON на Windows | В Python явно задавать `encoding='utf-8'` при чтении и записи JSON. До упаковки сверять декодированные названия материалов с исходной выгрузкой: последующая запись ASCII не исправляет уже испорченный текст. Кодировка выдаваемого JS — по [правилу 12](rules.md). |

## Как сократить повторные действия

Сначала читать модель через API. Разбор бинарного контейнера и поиск строк применять только к конкретному вопросу, который не решается штатным чтением; не использовать их для подсчёта деталей или восстановления актуальной геометрии. Интерфейс нужен для запуска, осмотра и независимых измерений, а не для переписывания свойств сотен объектов.

Проверенный инспектор, описание входных данных и сравнение сохранять рядом с ревизией. При следующем запуске сверять хеши и профиль среды; повторно получать только отсутствующие или изменившиеся доказательства. Один пакет проверок должен выдавать отдельные результаты случаев и итоговый протокол, чтобы не запускать скрипт вручную для каждого размера.

При расхождении после растяжения применить одинаковое изменение к копии исходной модели и к результату генерации. Это отделяет поведение исходных эластичных правил от ошибки переноса; предположение о потере скрытых свойств без такой пробы не считать установленной причиной. Сравнивать дерево и содержательные свойства с явно заданным допуском, а не байты сохранённых `.b3d`. Совпадение выгруженной геометрии не подтверждает невыгруженные операции, отсутствие коллизий и производимость.

Если цепочка увеличение → уменьшение → возврат сохраняет смещение рамки вложенного блока, повторные размеры получать перегенерацией из неизменного исходного базиса. Прямое растяжение в интерфейсе не объявлять полностью обратимым до исправления и проверки нативных ограничений, даже когда физическая геометрия вернулась на место.
