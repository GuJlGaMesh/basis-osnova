# Гейт подготовки скрипта: S0–S3

Открывать при подготовке или изменении выдаваемого `.js`. Вход — запрос, контракт параметров и выбранная [карточка мебели](../furniture/README.md). Результат — проверенный комплект для испытания в БАЗИС. Этот этап не требует уже построенной модели.

## Критерии

| Gate | Критерий PASS | Доказательство без запуска БАЗИС |
|---|---|---|
| S0. Контракт входов | Для всех обязательных параметров определены единицы, смысл и ограничения; значения подтверждены либо реализован обязательный запрос перед построением. Размерные цепи и зависимые элементы описаны | Паспорт, расчёт, перечень входов и проверка отказа при их отсутствии |
| S1. Реализация | Сохранён реальный `.js`; обязательные операции реализованы; методы опираются на применимую справку/проверенные примеры; нет псевдокода, недоступных неучтённых зависимостей и молчаливых замен | Ревью исходника, таблица API и источников, список материалов/библиотек, проверка структуры и синтаксиса с указанием инструмента и его границ |
| S2. Расчёт и поведение | Независимо проверены размерные цепи и граничные значения; код проверяет ввод до вставки, сохраняет текущую сцену и добавляет новый блок, не требует пустого документа; отмена/ошибки и повторный запуск обработаны | Расчётные примеры и результаты доступных проверок, ревью границ вставки и защитных веток; фактическое поведение API остаётся предметом G2 |
| S3. Комплект передачи | Файл доступен, ревизия и SHA-256 записаны; инструкция объясняет ручное открытие, ввод, запуск, ожидаемый результат и действия при ошибке; G0–G8 отражают реальное состояние | Комплект по [правилам выдачи](../releases.md), проверенные пути/ссылки и протокол |

S0–S3 обязательны. Кодировку проверять по [правилу 12](../rules.md): она относится к реализованному исходнику S1 и комплекту S3. Критические значения можно запросить при запуске; в этом случае до выдачи проверяют контракт отказа и формулы на явно заданных тестовых значениях. Конкретные значения изделия проходят G0/G1 до построения проверяемой модели.

Локальный БАЗИС, управление его окном, нативный файл модели и экспорты не являются условиями этого гейта. Проверка синтаксиса вне БАЗИС не подтверждает работу CAD API. Неподтверждённая обязательная операция или заглушка не считается реализацией S1.

## Рабочий маршрут

1. [Паспорт](../intake.md) и нужная карточка мебели: определить входы и размерные цепи.
2. [Построение скрипта](../bazis.md): реализовать ввод, расчёт и операции API.
3. [Проверки](../testing.md) и [ревью](../review.md): получить доказательства S0–S2.
4. [Выпуск](../releases.md): собрать файлы и закрыть S3.

Статус и блокирующие условия определяет [общая таблица решений](../quality-gates.md). Протокол — [шаблон qa.md](../templates/qa.md). После разрешённого запуска перейти к [гейту модели](model.md).
