# Изменение API или версии БАЗИС

## Когда применять

Новый CAD-метод, перенос скрипта на другую сборку или изменение адаптера API.

## Читать сначала

[Источники](../architecture/dependencies.md), [ограничения](../architecture/constraints.md), [работа в БАЗИС](../development/bazis.md).

Выбрать [гейт текущего этапа](../development/quality-gates.md) и только затронутую [карточку мебели](../development/furniture/README.md).

## Шаги

1. Установить исходную и целевую версии приложения и API, сохранить рабочий вариант.
2. Найти операции в справке целевой версии; записать отличия контракта.
3. Подготовить минимальный пример каждой изменяемой операции для ручного запуска человеком в отдельном документе.
4. Проверить доступную часть [регрессионных сценариев](../development/testing.md), закрыть S0–S3 и передать `.js` с инструкцией, включая сохранение, повторный запуск и отмену.
5. После ручной проверки обновить профиль совместимости. До неё указывать документальное основание выбора API и отсутствие проверки запуском; не обещать подтверждённую совместимость сборки.

## Чеклист

- [ ] Методы и единицы подтверждены справкой; результат ручного запуска записан отдельно либо отмечен NOT_RUN.
- [ ] Не смешаны поколения API.
- [ ] Ограничения совместимости явно записаны.

## Типовые ошибки

Предупреждаемые риски: считать год программы версией API; объявить совместимость после проверки синтаксиса в Node.js.
