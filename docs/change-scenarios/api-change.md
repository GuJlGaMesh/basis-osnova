# Изменение API или версии БАЗИС

## Когда применять

Новый CAD-метод, перенос скрипта на другую сборку или изменение адаптера API.

## Читать сначала

[Источники](../architecture/dependencies.md), [ограничения](../architecture/constraints.md), [работа в БАЗИС](../development/bazis.md).

## Шаги

1. Установить исходную и целевую версии приложения и API, сохранить рабочий вариант.
2. Найти операции в справке целевой версии; записать отличия контракта.
3. Проверить минимальный пример каждой изменяемой операции на отдельном документе.
4. Выполнить [регрессионные сценарии](../development/testing.md), включая сохранение, повторный запуск и отмену.
5. Обновить профиль совместимости и источники; выпускать только для проверенных сборок.

## Чеклист

- [ ] Методы и единицы подтверждены справкой и запуском.
- [ ] Не смешаны поколения API.
- [ ] Ограничения совместимости явно записаны.

## Типовые ошибки

Предупреждаемые риски: считать год программы версией API; объявить совместимость после проверки синтаксиса в Node.js.
