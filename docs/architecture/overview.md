# Архитектура процесса

Цель — воспроизводимое проектирование мебели с прослеживаемыми исходными данными. Область по умолчанию — корпусная мебель из плитных материалов. Для других конструкций сначала определяют применимые правила и критерии.

Поток работы: запрос → паспорт и выбранная карточка мебели → независимый расчёт → скрипт и комплект → выполнение в БАЗИС → проверенная модель → производственный допуск. Границы трёх этапов задаются [гейтами](../development/quality-gates.md); состав передаваемых файлов — [контрактом выпуска](../development/releases.md).

Паспорт хранит намерение пользователя, модель — фактическую геометрию, протокол — их сопоставление. Расчёт генератора не может быть единственным доказательством правильности фактической модели.

ИИ собирает параметры и готовит скрипт. Пользователь подтверждает исходные данные и новые конструктивные решения. Оператор — человек или агент при разрешённом доступе — выполняет скрипт в БАЗИС и получает фактические свидетельства. Технолог принимает производственное решение. Роли можно совмещать, но проверяющий и факт каждой проверки записываются явно.

Для действия открыть [маршрутизатор](../AGENTS.md), для размещения файлов — [слои](layers.md), для внешних зависимостей — [источники](dependencies.md) и [ограничения](constraints.md). Обоснования решений — в [ADR](../adr/README.md).
