# Архитектура процесса

Цель — воспроизводимое проектирование мебели с прослеживаемыми исходными данными и проверками. Область по умолчанию — корпусная мебель из плитных материалов. Для металлокаркаса, мягкой мебели, сложной криволинейной конструкции или нестандартных нагрузок сначала разрабатывают отдельные правила и критерии.

Поток разделён на два этапа:

1. Подготовка агентом: запрос → паспорт изделия → размерные цепи и конструкция → готовый `.js` → подготовительные проверки → комплект для ручного запуска.
2. Работа человека в БАЗИС: открыть и запустить скрипт → проверить построение → сохранить и повторно открыть модель → независимые измерения и деталировка → решение о готовности модели.

Результат работы агента на первом этапе — скрипт с сопроводительными документами по [правилам передачи](../development/releases.md). Доступ к окну БАЗИС на компьютере агента для этого не требуется. Критерии и статусы двух этапов определены в [quality gates](../development/quality-gates.md); подготовленный скрипт не подтверждает фактическое построение.

Паспорт хранит намерение пользователя. Модель хранит фактическую геометрию. Протокол сравнивает одно с другим; расчёт генератора не может одновременно быть единственным доказательством его правильности.

ИИ собирает параметры, предлагает конструкцию, готовит скрипт и выполняет доступные проверки. Пользователь подтверждает исходные данные и проектные решения. Оператор вручную запускает скрипт на компьютере с БАЗИС, сохраняет результат и возвращает сведения о выполнении и фактической модели. Технолог проверяет производимость и принимает решение о запуске в изготовление. Эти роли можно совмещать, но факт проверки и проверяющего записывают явно.
